# Git et GitHub

## C'est quoi ?

**Git** est un outil de **versioning** : il permet de sauvegarder l'évolution de son code dans le temps. Chaque sauvegarde s'appelle un *commit* — c'est une photo de l'état du projet à un instant T.

**GitHub** est une **plateforme en ligne** qui héberge les projets Git. Elle permet de stocker son code à distance, de collaborer à plusieurs, et de garder un historique accessible partout.

> En résumé : Git travaille en local sur votre machine, GitHub stocke et partage en ligne.

## Les concepts de base

- **Repository (repo)** : le dossier du projet versionné
- **Commit** : une sauvegarde horodatée avec un message descriptif
- **Branch** : une version parallèle du projet pour tester sans toucher au principal
- **Push** : envoyer ses commits locaux vers GitHub
- **Pull** : récupérer les dernières modifications depuis GitHub
- **Clone** : copier un repo existant sur sa machine

## Pourquoi c'est utile

- Ne plus jamais perdre une version qui marchait
- Travailler à plusieurs sans s'écraser mutuellement
- Comprendre qui a changé quoi, et pourquoi
- Déployer un site ou une application directement depuis GitHub
